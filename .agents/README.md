# Агентская обвязка

## 1. Источник правил

[AGENTS.md](../AGENTS.md) содержит общие требования. Skills описывают процедуры, роли — ответственность исполнителей. Адаптеры Codex, Claude Code и Cursor ссылаются на канонические файлы. Общая основа адаптирована из ContentAI-Frontend, QA/UX/интеграции и части эксплуатации — из Purpur. Привязки к бренду, корпоративным сервисам и обязательному виртуальному отделу исключены.

| Skill                                                    | Когда применять                                                                  |
| -------------------------------------------------------- | -------------------------------------------------------------------------------- |
| [dev-cycle](skills/dev-cycle/SKILL.md)                   | Рабочий цикл, владение папкой и передача результата                              |
| [design-and-docs](skills/design-and-docs/SKILL.md)       | Исследование, требования и долговременные решения                                |
| [build-and-test](skills/build-and-test/SKILL.md)         | Команды проверок, диагностика, регрессии, браузер и CI                           |
| [quality-assurance](skills/quality-assurance/SKILL.md)   | Приёмка по требованиям, исследовательские проверки и повторная проверка дефектов |
| [ux-design](skills/ux-design/SKILL.md)                   | Пользовательские сценарии, адаптивность, доступность и состояния интерфейса      |
| [integration-design](skills/integration-design/SKILL.md) | Контракты API/данных, повторы, частичный успех и восстановление                  |
| [simplify-solution](skills/simplify-solution/SKILL.md)   | Упрощение решений и удаление доказанно неиспользуемого кода                      |
| [github](skills/github/SKILL.md)                         | GitHub Issues, ветки, PR и Actions                                               |
| [timeweb](skills/timeweb/SKILL.md)                       | SSH, поставка статических/PHP-приложений и восстановление                        |
| [skill-doctor](skills/skill-doctor/SKILL.md)             | Аудит skills, ролей, адаптеров и согласованности инструкций                      |
| [claude-api](skills/claude-api/SKILL.md)                 | Интеграции Claude API в выбранном приложении                                     |

`skill-doctor` проверяет качество и согласованность инструкций. `npm run check:harness` проверяет структуру и ссылки, `npm run doctor` — окружение и подключения. Пример запроса: «Используй $skill-doctor для аудита обвязки».

`quality-assurance` определяет ожидаемое поведение, а `build-and-test` — способ его проверить. UX задаёт видимые состояния, интеграции — значение результата между системами. Подробности диагностики и восстановления загружаются только для соответствующей задачи. Источники и решения — в [описании обвязки](../docs/designs/agent-harness.md).

## 2. Роли и среды

| Роль                          | Ответственность                                                                   |
| ----------------------------- | --------------------------------------------------------------------------------- |
| [planner](roles/planner.md)   | Исследование и план без записи                                                    |
| [coder](roles/coder.md)       | Реализация в порученных файлах                                                    |
| [reviewer](roles/reviewer.md) | Анализ кода и дизайна без записи                                                  |
| [qa](roles/qa.md)             | Проверка поведения и порученные тесты, без скрытого исправления приложения        |
| [designer](roles/designer.md) | Порученные спецификации, материалы и прототипы, состояния и передача в реализацию |

Роли наследуют модель и ограничения родительской среды. Наличие файла не запускает подагента, не расширяет права и не обеспечивает отдельный read-only sandbox. Разделение обязанностей само по себе не делает авторскую проверку независимой. Делегирование применяется только когда разрешено пользователем или действующими инструкциями среды.

Claude Code читает `CLAUDE.md`, Codex и Cursor — `AGENTS.md`. Адаптеры skills Claude Code находятся в `.claude/skills/`. Роли представлены в `.codex/agents/`, `.claude/agents/`, `.cursor/agents/`. `npm run check:harness` обнаруживает канонические роли и проверяет наличие, имена и ссылки всех трёх адаптеров, включая лишние адаптеры без исходной роли.

Сведения о подключениях — в [GitHub](../docs/github.md) и [Timeweb](../infra/timeweb/README.md). Дизайн не требует подключения внешнего редактора. Каждый app сохраняет собственный стек и визуальные правила.

## 3. Форматирование

Хук [format-touched.cjs](hooks/scripts/format-touched.cjs) обрабатывает пути из событий сред и форматирует только существующие изменённые файлы через ближайший установленный Prettier. Чужие пути, выходящие за проект symlink, секреты и личная конфигурация пропускаются. Хук не ищет форматтер в соседних приложениях и не устанавливает пакеты.

Конфигурации находятся в `.codex/hooks.json`, `.claude/settings.json` и `.cursor/hooks.json`. Поддержка и включение hooks зависят от среды. Наличие конфигурации не подтверждает запуск хука. Ошибка форматирования выводится в stderr и не блокирует редактирование. Обязательная проверка — `npm run format:check` и CI.

[Проверка hooks](hooks/README.md) содержит условия доверия, команды повторного запуска и границы свидетельств. Подтверждены native Codex CLI `apply_patch` → `PostToolUse`, Claude Code CLI `Write` → `PostToolUse` и Cursor GUI `afterFileEdit`. В CLI-прогонах ответ модели заменён локальной детерминированной фикстурой. Проверка wrapper `functions.exec` не дала автоматического форматирования, поэтому успешный native CLI-прогон на него не распространяется. Эти проверки не оценивают автоматический выбор skills коммерческими моделями.
