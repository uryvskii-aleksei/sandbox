# Design and documentation

Read the requested outcome, owning code, latest issue/PR when relevant and settled decisions. Preserve human edits. Ask only about consequential ambiguity, such as a missing deployment domain or an incompatible public contract. Continue independent work.

- For research and technical decisions, use [research](references/research.md).
- For human documentation and contracts, use [writing](references/writing.md).
- For interrupted or resumed work, use [handoff](references/handoff.md).

Separate verified facts, recommendations and unresolved questions. A design explains lasting behavior and reasons. A plan describes execution. Keep a local plan in chat and an authorized PR plan in `## План`. Do not create a repository progress log or duplicate an existing canonical design.

Choose an [owned workspace](../dev-cycle/references/task-worktree.md) before writing files. Editorial fixes need no architecture review. Verify affected links and examples and report publication status accurately.
