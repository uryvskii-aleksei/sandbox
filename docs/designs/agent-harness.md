# Агентская обвязка Sandbox

## 1. Задача и источники

Обвязка должна помогать разрабатывать независимые приложения на macOS и публиковать их через GitHub и виртуальный Timeweb. Нужны точные условия включения skills, реальные проверки и понятное владение файлами. Исследование выполнено 23 ноября 2026 года через веб-поиск, официальную документацию и Habr.

[Agent Skills](https://agentskills.io/skill-creation/best-practices) рекомендует начинать с реального рабочего опыта, включать только недостающие агенту знания, загружать подробности по необходимости и улучшать skill по результатам выполнения. Для нас это основание держать короткие entrypoint-файлы и ссылки на процедуры конкретного приложения.

[Anthropic о Skills](https://www.anthropic.com/research/equipping-agents-for-the-real-world-with-agent-skills) описывает загрузку в несколько уровней: сначала метаданные, затем инструкция, затем дополнительные ресурсы. Значит, широкое описание skill само по себе создаёт лишние включения, даже если его основной текст хорошо организован.

[Документация subagents](https://code.claude.com/docs/en/sub-agents) предлагает отдельный контекст для ограниченной побочной задачи и постоянную роль при повторении одного вида работы. Для Sandbox это означает ограниченные роли с точными входами и результатами. Состав выбран под реальные обязанности: планирование, реализация, ревью, приёмка и UX. Каждое изменение не обязано проходить через всех исполнителей.

На Habr изучены [«Три паттерна написания Agent Skills»](https://habr.com/ru/articles/1065860/) и [практический пример ролей в Claude Code](https://habr.com/ru/articles/974924/). Первый материал полезен разбором связности и разделения задач. Во втором интересен контракт роли: входные материалы, результат и ограничения. Это опыт авторов, а не спецификация рантайма. Технические возможности сверяются с официальной документацией.

## 2. Что сохраняем

Один `AGENTS.md` задаёт общие правила. Skills описывают процедуры. Роли planner/coder/reviewer/qa/designer определяют ответственность. Адаптеры сред ссылаются на канонические файлы. Форматирование и проверки реализованы исполняемыми командами, а наличие файла роли не объявляется технической изоляцией инструментов.

Подробности тестирования и поставки остаются рядом с приложением. Сохраняется различие между локальным результатом, коммитом, публикацией в GitHub и деплоем. Уже данное поручение на публикацию не требует повторного запроса разрешения на каждый промежуточный шаг.

## 3. Состав и адаптация

Добавлен адаптированный [claude-api](../../.agents/skills/claude-api/SKILL.md). Он включается для интеграций Claude API и не включается при обычной работе над репозиторием, ролями или SSH. Убраны фиксированная премиальная модель, широкий перехват задач с неуказанным провайдером и рекомендации включать thinking независимо от стоимости. Сохранены проверка актуальной документации, использование подходящего официального SDK, обработка streaming/tool calls и серверное хранение ключей.

Skill учитывает независимые стеки монорепозитория. Для MindAssistant это PHP-сервер на Timeweb и React в браузере. Установка skill не добавляет Claude в продукт, не устанавливает SDK и не совершает платных API-вызовов. Лицензия Apache-2.0 сохранена. Оригинал — [anthropics/skills](https://github.com/anthropics/skills/tree/main/skills/claude-api).

Из Purpur адаптированы [quality-assurance](../../.agents/skills/quality-assurance/SKILL.md), [ux-design](../../.agents/skills/ux-design/SKILL.md), [integration-design](../../.agents/skills/integration-design/SKILL.md), роли [qa](../../.agents/roles/qa.md) и [designer](../../.agents/roles/designer.md). QA отделяет ожидание от фактического поведения. UX задаёт состояния и доступность для конкретного приложения. Интеграции описывают владение данными, повторяемость и неизвестный результат операции. Роли не привязаны к бренду, магазину, CTO или внешнему редактору.

`build-and-test` дополнен [диагностикой](../../.agents/skills/build-and-test/references/diagnose-failures.md): воспроизведение, первый сбой, гипотеза, минимальная проверка и регрессия. `timeweb` дополнен [восстановлением](../../.agents/skills/timeweb/references/recovery.md) и [PHP/MySQL](../../.agents/skills/timeweb/references/php-mysql.md). Сохранены различия между откатом файлов, восстановлением базы и согласованием внешних эффектов. Статический помощник по-прежнему не выполняет PHP-поставку или миграции.

У приложений есть реальные команды: тесты сайтов, сборки React и PHP/MySQL integration test с отдельной БД и проверкой собранного артефакта. Проверка обвязки обнаруживает все роли и проверяет адаптеры Codex/Claude Code/Cursor. Автотесты валидатора проверяют обнаружение новой роли, отсутствие/неверное направление адаптера и оставшийся адаптер удалённой роли. Это проверка конфигурации, не независимый поведенческий эксперимент с агентом.

Полная старая обвязка сохранена в архивной истории. Активные инструкции не требуют Figma/TFS, отдельного CTO-inbox, регистрации каждого запроса в `tasks/` или автоматического production-деплоя.

## 4. Границы переноса

| Материалы Purpur                                                  | Решение для Sandbox                                                                                            |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| QA, UX, интеграции, qa/designer                                   | Адаптированы в общую обвязку                                                                                   |
| Диагностика, эксплуатация и восстановление                        | Включены в `build-and-test` и `timeweb`, без ещё одной системы дублирующих skills                              |
| Продуктовые цели, критерии приёмки, достоверные материалы         | Полезные положения включены в QA/UX. Отдельные PO/BA роли не добавлены                                         |
| Архитектурные контракты и переходы схем                           | Используются в интеграциях и процедурах поставки                                                               |
| Маркетинг, продажи, BI, каталог                                   | Сохранены в архиве. Подключаются под конкретную продуктовую задачу, не как общие требования каждого приложения |
| Виртуальный отдел, локальная база задач, корпоративные интеграции | Исключены из активной обвязки. Учёт задач — GitHub, долговременные решения — owning app/docs                   |
| Общие dev-cycle, review, hooks и адаптеры                         | Используется существующий источник Sandbox. Дублирование из Purpur не включается                               |

## 5. Возможное развитие

| Предложение                      | Основание и условие                                                                                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Поведенческие прогоны skills     | При изменении условий включения проверять реальные запросы и наблюдать действия. Валидатор YAML не доказывает качество решений                                |
| Автоматизация поставки PHP/MySQL | У MindAssistant уже есть инструкция поставки. Автоматизацию добавлять под конкретную БД, каталог, резервное копирование и миграции                            |
| Отдельный навык переноса данных  | Когда потребуется импорт старого PostgreSQL-дампа: явный владелец, проверяемое преобразование схемы, тест и rollback                                          |
| Специализированного reviewer     | Только если повторяются пропуски определённого класса. Например, безопасность PHP или миграции БД. Новая роль должна иметь собственный ограниченный результат |

Не добавляем автоматически десятки ролей, обязательные длинные планы, загрузку всех справочников, дублирующие skills для каждого языка или таймерные циклы проверок. Они оправданы только наблюдаемой пользой. Добавление ролей не означает, что выполнено независимое ревью или QA. Валидация файлов и авторские проверки указываются отдельно.

## 6. Сценарии оценки

| Запрос                                       | Ожидаемое решение                                                                                                                |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| «Исправь цвет кнопки Purpur»                 | Обычная разработка и проверка сайта. Claude API skill не нужен                                                                   |
| «Добавь Claude-сводку в MindAssistant»       | Claude API skill, PHP API, проверка владельца, серверный ключ. Не Node-сервер на shared hosting                                  |
| «Исправь существующий OpenAI-клиент»         | Сохранить провайдера. Не заменять его Anthropic                                                                                  |
| «Изучи варианты размещения»                  | Исследование и вывод. Не покупка хостинга и не деплой                                                                            |
| «Опубликуй проверенное приложение в Sandbox» | Проверки, scoped commit/push, проверка удалённого SHA и CI. Без повторного вопроса о уже порученной публикации                   |
| «Составь приёмку сохранения карточки»        | QA: критерий сохранения после обновления, отдельные данные, отрицательные случаи. Не переписывать код для совпадения с ожиданием |
| «Проработай мобильный диалог приложения»     | UX: состояния, фокус, экранная клавиатура и правила приложения. Без навязывания бренда или внешнего редактора                    |
| «Повтори запись после таймаута»              | Интеграции: выяснить результат и контракт дедупликации до повторения эффекта                                                     |
| «Подготовь откат PHP-приложения»             | Timeweb: артефакт, совместимость схемы, резервная копия и восстановление. Не запускать live restore как тест                     |
| «Проверь доступ к Timeweb»                   | Read-only SSH check. Не замена сайта                                                                                             |

Это набор для ручного прогона или независимой оценки, когда она разрешена. Форматирование, валидатор и просмотр сценариев не обозначаются как выполненный поведенческий эксперимент.
