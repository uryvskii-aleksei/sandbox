# Поставка MindAssistant на Timeweb

## 1. Окружение

Целевой стек — обычный виртуальный хостинг с Apache, PHP 8.4, PDO MySQL, curl, DOM и fileinfo. На аккаунте проверены PHP 8.4.28, драйвер PDO MySQL и curl. Версию PHP для веб-сайта нужно сверить в панели отдельно от SSH CLI.

Базовый путь React — `/mind-assistant/`. Выделенный каталог — `public_html/mind-assistant`, после его явного создания. Корневой Purpur и `stonehaus/` не заменяются. Статический помощник `npm run timeweb` не выполняет поставку PHP и миграции БД.

## 2. Подготовка

1. Создайте MySQL-базу и пользователя в панели Timeweb. Не записывайте пароль в Git или чат.
2. Скопируйте `backend/config.example.php` в приватный конфигурационный файл на сервере. Задайте `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `APP_ENV=production`.
3. Настройте `MIND_ASSISTANT_CONFIG` на путь вне `public_html`, если окружение позволяет. Иначе используйте `config.local.php` в корне выделенного приложения. Сборка запрещает HTTP-доступ к `config.*.php`, `backend/` и `database/` через `.htaccess`. Проверяйте запрет до добавления реальных реквизитов.
4. Выполните локальные проверки и `npm run build:mind-assistant`. Перед заменой приложения сохраните прежний артефакт и резервную копию MySQL вне публичного сайта.

## 3. Поставка

Передавайте только содержимое `apps/mind-assistant/dist/` в выделенный каталог. Не используйте `--delete` без отдельного понимания серверных файлов. Не перезаписывайте `config.local.php`. Не публикуйте исходный монорепозиторий, `.env` или приватный дамп.

Примените схему по SSH из корня приложения:

```bash
php database/migrate.php
```

Миграция создаёт отсутствующие таблицы и повторно выполняется без удаления записей. Будущие изменения существующих таблиц требуют отдельных версионных миграций и резервной копии. Старый PostgreSQL-дамп не является MySQL-миграцией.

## 4. Проверка и восстановление

Проверьте HTTPS, `/mind-assistant/api/health`, обновление вложенного маршрута `/mind-assistant/workplace/<id>`, запрет доступа к `config.local.php`, `backend/bootstrap.php` и `database/schema.sql`. Затем проверьте регистрацию, вход, создание/сохранение проекта, карточки и файла, выход и повторный вход. Используйте отдельного тестового пользователя.

Откат файлов не откатывает БД. При несовместимом изменении восстанавливайте согласованную пару артефакта и резервной копии базы. Не удаляйте записи других приложений и общие каталоги хостинга.
