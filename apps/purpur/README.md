# Пурпур

## 1. Исходники

Снимок сайта с Timeweb: основной экран, `concept/`, варианты `purpur/v1/`, `purpur/v2/`, `purpur/v3/`, изображения, локальные шрифты, видео и PHP-обработчики. Исходные файлы в `site/` сохранены без переформатирования. `repository-main.html` — отдельная версия главного экрана из прежнего GitHub-репозитория. Она использует общие ресурсы из корня сайта.

v2 и v3 используют абсолютные пути к ресурсам v1. При публикации нужно сохранять дерево URL. `concept/` на production перенаправляется в корень правилами `.htaccess`.

## 2. Запуск и проверка

Из корня монорепозитория:

```bash
npm ci
npm run dev:sites
npm test --workspace=@sandbox/purpur
npm run build --workspace=@sandbox/purpur
```

Локальные адреса: `http://127.0.0.1:4173/`, `/repository-main.html`, `/concept/`, `/purpur/v1/`, `/purpur/v2/`, `/purpur/v3/`. Предпросмотр показывает статические страницы. PHP возвращает 501 и не раскрывает исходники. Для PHP нужен совместимый сервер с curl и mail. Реальную отправку заказов нельзя использовать как локальный smoke-тест.

Сборка создаёт отдельный `dist/`, сохраняя файлы сайта. Тесты перенесены из прежнего репозитория. Логика проверок сохранена, пути адаптированы к монорепозиторию. Они проверяют корзину, каталог из 221 товара, сценарии заявок, порядок каталога и фоновое видео. `catalog-audit.json` — исторический источник состава каталога, не актуальный прайс.

## 3. Документы и происхождение

[Архив документации](archive/docs/site-brief.md), [backlog](archive/tasks/README.md) и [старое описание](archive/README.md) сохранены с исходными формулировками и ссылками. Упоминания старых путей, Figma, TFS и виртуального отдела относятся к истории проекта и не задают правила Sandbox. Действующие правила находятся в корневом `AGENTS.md`.

История веток и происхождение файлов описаны в [реестре импорта](../../docs/imports/README.md). Старый локальный checkout не изменяется переносом.

## 4. Публикация

Текущий сайт: [cj999935.tw1.ru](https://cj999935.tw1.ru/). Команды `node scripts/deploy-sites.mjs plan purpur` и `publish purpur --apply` из корня Sandbox проверяют актуальный `main`/CI, сохраняют backup и обновляют только принадлежащие Purpur файлы. Общий document root и соседние приложения сохраняются. Первичная установка, HTTPS-проверки и восстановление — в [процедуре поставки](deployment.md). Универсальный статический помощник не заменяет эту PHP-процедуру.
