# Проверка восстановления Memo

## 1. Изолированная репетиция

Проверка восстанавливает SQL-копию в отдельный случайно названный Docker Compose-проект с PHP 8.2 и MySQL 8.4. Production и обычный локальный volume приложения не используются. База наружу не опубликована, API слушает только `127.0.0.1` на свободном порту. Письма, фоновые задания и URL-превью не вызываются.

Получите нужную копию из приватного `~/.sandbox/mind-assistant/backups/` по существующему SSH alias с `StrictHostKeyChecking=yes`. Сохраните её вне Git или в `.imports/private/mind-assistant/restore-tests/` с правами `600` и каталогом `700`. Не копируйте SQL в публичный `public_html`, чат или CI-артефакты.

```bash
npm run test:restore:memo -- \
  --backup .imports/private/mind-assistant/restore-tests/BACKUP.sql \
  --require-populated
```

Нужны Node.js 24+, Docker Desktop и свободное место. `--require-populated` предназначен для копии с данными. Для действительно пустой базы опустите этот флаг.

## 2. Что подтверждает команда

Скрипт восстанавливает SQL и проверяет обязательные таблицы, отсутствующие родительские/владельческие связи, проекты, карточки, поля и медиа через API. Все таблицы, включая журнал импорта, участвуют в контрольной сумме содержимого до и после проверки.

Для входа в восстановленную копию временно меняется пароль только пользователя из этой изолированной БД. Исходный hash сохраняется внутри тестового контейнера, восстанавливается перед итоговой сверкой и не выводится. Production-пароли не меняются. Результат содержит SHA самой SQL-копии, количества записей, проверки связей, объём API-проверки и время, без названий проектов, содержимого и email.

По завершении удаляются только контейнеры, сеть, volume и временные файлы этой попытки. Исходная SQL-копия остаётся приватной.

## 3. Проверенный результат

Реальная копия после переноса legacy-данных успешно восстановлена: 1 пользователь, 3 проекта, 5 карточек, 2 группы, 2 поля, 1 запись журнала импорта. Нарушенных связей нет. Через API проверены все 5 карточек и 2 поля. Контрольная сумма полного содержимого до/после совпала. Отдельная копия с синтетическими данными дополнительно подтвердила восстановление и выдачу медиа.

Это проверка восстановления backup в изоляции. Живая production-БД не заменялась. Для её восстановления сначала определите причину, нужную пару файлов/схемы/данных, изменения после backup и допустимость их потери. Файловый возврат receiver не откатывает БД.
