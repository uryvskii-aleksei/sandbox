# Amodu

Главная [amodu.ru](https://amodu.ru/) с примером полотна Memo и ссылками на проекты Sandbox.

## 1. Предпросмотр

Из корня монорепозитория запустите статический сервер и откройте [127.0.0.1:4181](http://127.0.0.1:4181/). После правок обновите страницу в браузере.

```bash
python3 -m http.server 4181 --bind 127.0.0.1 --directory apps/amodu/site
```

HTML, стили и изображения лежат в `site/`. Сборка и зависимости для предпросмотра не нужны. Ссылка «Wave» открывает приложение по пути `/wave/`. Чтобы проверить переход и сам плеер локально, используйте [совместный предпросмотр](../wave/README.md#1-локальный-запуск).

## 2. Изображения

Фотография Stone Haus используется в [концепции v2](../stonehaus/site/v2/index.html). Для «Пурпура» взят [кадр из видео](../purpur/site/assets/purpur-film-poster.jpg). Карточка «Wave» использует уменьшенную версию [иллюстрации, созданной в ImageGen](../wave/site/assets/station.jpg). Полотно Memo собрано в HTML и CSS, данные в нём вымышленные.

## 3. Публикация

`npm run build:sites -- amodu` создаёт `dist/` для публикации проверенного коммита `main`. В опубликованном HTML стили и изображения загружаются из `/amodu/`.

```bash
npm run build:sites -- amodu
npm run timeweb -- check amodu
npm run timeweb -- plan amodu
npm run timeweb -- publish amodu --apply
```

Артефакт поставляется в каталог `/home/c/cj999935/public_html/amodu` цели `amodu` из [реестра Timeweb](../../infra/timeweb/targets.json). На первой поставке создайте этот выделенный каталог и проверьте содержимое `https://amodu.ru/amodu/`. Затем сохраните резервную копию общего `.htaccess` вне `public_html` и атомарно добавьте [правило Amodu](deploy/root-route.conf) после существующего правила перенаправления на HTTPS. Проверьте `https://amodu.ru/`, его ресурсы, техническую главную и действующие адреса приложений. При ошибке первой публикации восстановите предыдущий `.htaccess` из копии после сверки, что он не менялся параллельно.
