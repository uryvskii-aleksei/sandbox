| ----------------------------------------- | -------------------------------------------------------------------------------------------- |
| Timeweb `public_html`, кроме `stonehaus/` | `apps/purpur/site/`, 996 исходных файлов                                                     |
| Timeweb `public_html/stonehaus/`          | `apps/stonehaus/site/`, 9 файлов                                                             |
| `uryvskii-aleksei/purpur`                 | Отличающийся экран `repository-main.html`, аудит каталога, тесты, архив документации и задач |

## 2. История Purpur

Архивные ветки Sandbox используют префикс `archive/purpur/`. В них сохраняются исходные коммиты и деревья, включая старую обвязку. Ветка `archive/purpur/local-stonehaus-v2` сохраняет локальную работу поверх прежнего HEAD, не изменяя соседний checkout. PR head/merge refs сохраняются как `archive/purpur/pr-N-head` и `pr-N-merge`, если они присутствуют у источника.

Для просмотра истории после публикации:

```bash
git fetch origin 'refs/heads/archive/purpur/*:refs/remotes/origin/archive/purpur/*'
git log origin/archive/purpur/main
git show origin/archive/purpur/main:README.md
```

Локальные зеркала `.imports/git/` являются дополнительной копией и не входят в коммит. Issues, обсуждения и метаданные PR сохраняются отдельным JSON-снимком рядом с этим документом. Git не переносит объекты GitHub Issues и PR автоматически.

## 3. История MindAssistant

Frontend и Backend сохранены в ветках `archive/mind-assistant/frontend/{master,develop}` и `archive/mind-assistant/backend/{master,develop}`. Frontend сохраняет исходные SHA. Из истории Backend удалены файлы PostgreSQL-дампов `sql` и `mindassistant`, поэтому его SHA отличаются. Авторы, сообщения, порядок и история изменений кода сохранены. Исходные SHA и архивные SHA зафиксированы в реестре и [карте 35 коммитов Backend](mind-assistant-backend-commits.json).

[Снимок GitHub](mind-assistant-github.json) сохраняет две задачи Backend, включая незавершённые продуктовые идеи, и фиксирует отсутствие PR и releases. В Frontend задач, PR и releases нет. Git-история не создаёт новые GitHub Issues автоматически.

Непустой исторический дамп содержит 1 проект и 5 записей. Он сохранён с правами 600 в `.imports/private/mind-assistant/legacy-historical-postgresql.dump`, исключён из публичной истории. Исходные зеркала `.imports/git/alekseiu/` сохраняют оригинальную историю локально. Эти приватные копии не переносятся обычным clone Sandbox и должны сохраняться отдельно от удаляемых старых checkout-папок. Исторический дамп сконвертирован и импортирован в MySQL с явным назначением владельца и восстановлением двух отсутствующих исходных проектов. Правила — в [миграции MindAssistant](../../apps/mind-assistant/migration.md).

## 4. Исторические документы

`apps/purpur/archive/` и `apps/stonehaus/archive/` содержат исходные материалы. Ссылки могут отражать старое дерево репозитория. Проверка локальных ссылок Sandbox не переписывает эти документы. Для исходного расположения используйте архивную ветку. Figma/TFS и старые роли не подключаются как действующие интеграции.

## 5. Данные MindAssistant

Оригинальный PostgreSQL-дамп находится в игнорируемом `.imports/private/mind-assistant/legacy-postgresql.dump` с правами 600. Он исключён из публичного Git вместе с возможными пользовательскими данными. Старые исходники сохранены с лицензиями. Новое приложение использует React + PHP + MySQL. Его конфигурация и локальные данные также исключены из Git.

Дамп последнего коммита проверен через `pg_restore --data-only`: в `projects`, `data`, `field_groups` и `fields` по 0 записей. Более ранний непустой дамп описан в разделе истории MindAssistant. Новая MySQL-схема создаётся отдельно. Исторический непустой дамп перенесён: 3 проекта (включая два восстановленных), 5 карточек, 2 группы и 2 поля. Повторная проверка журнала подтвердила отсутствие дублей. Копия новой MySQL-базы после импорта успешно восстановлена в изолированном Docker с проверкой API и всех связей. Персональные данные, адрес владельца и содержимое записей в Git не публикуются.
