# Публикация Wave на Timeweb

## 1. Назначение

[Реестр Wave](deploy/timeweb.json) задаёт адрес и выделенные каталоги приложения. Нужен веб-PHP 8.2+ с PDO SQLite. Веб-PHP Timeweb записывает в выделенный каталог `public_html/.wave-data` с правами `0700`. Установите в него [правило доступа](deploy/data.htaccess) под именем `.htaccess`. До инициализации базы проверьте, что на обоих доменах хостинга HTTPS возвращает 403 или 404 для пробных файлов с расширениями `.sqlite3`, `.sqlite3-journal`, `.sqlite3-wal` и `.sqlite3-shm`. В каталоге размещаются только база и служебные файлы SQLite. Копии храните вне document root. Для локального запуска и других хостингов переменная `WAVE_DB_PATH` задаёт абсолютный путь к базе вне document root.

## 2. Сборка и поставка

1. Возьмите коммит `main` с успешным Harness. Выполните `npm ci`, `npm run build:sites -- wave` и сверку `apps/wave/dist/`. В каталог поставки входят только файлы из `site/`.
2. Проверьте через SSH состояние выделенных каталогов и свободное место. Создайте отдельный временный каталог релиза вне document root. Передайте в него только содержимое `apps/wave/dist/` через rsync по SSH, включая `.htaccess`. Сверьте SHA-256 файлов на сервере с артефактом.
3. При первом выпуске создайте закрытый каталог данных и переместите проверенный каталог сборки на место `public_html/wave`. При обновлении сохраните предыдущий каталог Wave вне document root и сделайте согласованную копию SQLite через SQLite Backup API. Затем смените только каталог приложения Wave.
4. Проверьте [плеер](https://amodu.ru/wave/), JavaScript, доступ к API и запуск клипа. Гостевой API должен вернуть JSON, а каталог базы должен остаться вне HTTP-доступа. После проверки обновите [главную Amodu](../amodu/README.md), если изменена карточка.

## 3. Возврат

Если после обновления HTTPS или API не проходят проверку, сохраните ошибочный каталог вне document root и верните предыдущий каталог Wave. Для первой публикации уберите только каталог этого релиза из публичной зоны и отложите обновление карточки. Файловый возврат сохраняет текущую базу. Восстановление копии базы требуется только при отдельно установленном повреждении данных.
